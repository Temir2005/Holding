# Общий бриф для прототипов этапа 0

Ты делаешь **один** статичный HTML-прототип концепции редизайна сайта холдинга MegaSmart (Шымкент, Казахстан): девелопмент, производство МДФ-панелей (Smart Panels) и новые проекты в Alatau City. Полный цикл: земля → проект → собственные материалы → стройка → сдача. Планка ремесла: Linear / Stripe / Vercel, перенесённая на мир архитектуры, материалов и стройки.

**Что будет оцениваться:** типографика, композиция, ритм, движение и фирменный приём. Фото пока нет, вместо них нейтральные плашки (`MS.plate()`). Потом там будут реальные фото архитектуры, стройки и производства, поэтому композиция должна быть рассчитана на крупные фото.

## Файлы
- Работать только в `design/concepts/<name>/`: `index.html`, `style.css`, `motion.js`, при желании `README.md` с заметками. Ничего вне этой папки не менять. В `_shared/` только читать.
- В `index.html` подключить в таком порядке:
  1. `../_shared/fonts.css`
  2. `style.css`
  3. `../_shared/content.js`
  4. `../_shared/harness.js`
  5. `motion.js` (через `defer`)
- Без CDN, сборки и библиотек: только ванильный JS и CSS.

## Данные: ничего не хардкодить
- Весь контент рендерится из `window.MS` (`_shared/harness.js`). В HTML остаётся только каркас (`<header>`, `<main>`, пустые `<section data-block="...">`). JS заполняет их из `MS.hero`, `MS.stats`, `MS.process`, `MS.showcase`, `MS.nav`, `MS.ui('status.completed')`, `MS.t(localized)`, `MS.num(n)`, `MS.esc()`.
- Обязательно поддержать стресс-параметры harness: `?lang=kk|en`, `?n=0|1|3|12`, `?tone=dark|light|accent`, `?menu=open`.
  - При `n=0` блок не ломается: заголовок секции остаётся, вместо списка аккуратное пустое состояние (`MS.ui('empty')`) или блок схлопывается красиво.
  - `n=1` и `n=12` тоже должны выглядеть намеренно.
- У секции `stats` нет eyebrow и title (`null`), это нормально: блок должен выглядеть законченным и без них.
- Tone секции берётся из `MS.sectionTone(section)`, hero всегда `dark`. Каждый блок должен хорошо выглядеть на `dark`, `light` и `accent`. Реализуй тона через классы `.tone-dark`, `.tone-light`, `.tone-accent`, которые переопределяют семантические CSS-переменные (`--surface`, `--fg`, `--fg-mute`, `--line`, `--accent`…). На сайте сейчас сделано так же, это нужно для переноса.
- Числа выводятся через `MS.num()`, единицы (`suffix`) — частью композиции.
- Фото выводятся через `MS.plate(media)`, стиль `.ms-plate` и `.ms-plate__label` задаёшь сам. Плашка должна выглядеть как «место под кадр», а не как сломанная картинка: тонкая штриховка или тон, моно-подпись.

## Что должно быть на странице (в этом порядке)
1. **Шапка + hero главной** (`MS.hero`): eyebrow, title, subtitle, 2 CTA, фон или фото, swatches (образцы панелей с кодами RAL/LAB), если они вписываются в концепцию.
2. **stats** (`MS.stats.items`): цифры-герои, они должны быть огромными и запоминаться.
3. **process_steps** (`MS.process`): «полный цикл», 5 этапов. Это фирменный момент сайта.
4. **projects_showcase** (`MS.showcase.items`: title, status, location, year, area_m2, is_tokenized, short, cover): композиция с крупными изображениями (плашками), статусы, площади, годы, ссылка `MS.showcase.link`.
5. **Мобильное меню:**
   - на ≤ 768 кнопка «Меню», меню открывается на весь экран;
   - при `?menu=open` меню открыто сразу, без анимации;
   - фокус-ловушка, закрытие по Esc;
   - внутри пункты навигации, переключатель языков RU / KZ / EN (ссылки на `?lang=`), контакты из `MS.C.site.contacts`.
6. Короткий подвал-заглушка с контактами, чтобы было видно, чем страница заканчивается. Простой, без претензий.

## Жёсткие требования
- **Адаптив 375–1920** без горизонтального скролла. Проверяй 375 и 1440, мысленно 768 и 1920.
- **Казахский длиннее:** `?lang=kk` на 375 не ломает hero и заголовки. Используй `hyphens: auto` + `lang`, `overflow-wrap: anywhere` для длинных слов, `clamp()` в размерах шрифтов.
- **Контраст WCAG AA** для текста на всех тонах. Видимый `:focus-visible` у всего интерактивного, ссылки и кнопки настоящие (`<a>`, `<button>`). Есть skip-link. Порядок заголовков h1 → h2 → h3.
- **Движение:**
  - каждое движение объясняет структуру или ведёт взгляд;
  - только `transform`, `opacity`, `clip-path` и SVG `stroke-dashoffset`;
  - можно CSS scroll-driven animations (`animation-timeline: view()/scroll()`) под `@supports`, с фолбэком на IntersectionObserver;
  - **при `prefers-reduced-motion: reduce` отключается всё, кроме прозрачности**, и контент сразу в финальном состоянии;
  - на сайте всё это потом будет сделано на Framer Motion (`useScroll`, `useTransform`, `whileInView`), поэтому не делай ничего, что требует GSAP или плавного скролла.
- **Без layout shift:** размеры плашек известны (aspect-ratio), шрифты с `font-display: swap`.
- **Избегать клише:** градиентные блобы, glassmorphism, всё по центру, одинаковые карточки с тенями 3×N, эмодзи-иконки, кастомный курсор, marquee как единственная динамика, параллакс, от которого укачивает, текст поверх фото без контраста.
- Каждая секция должна стоять на своих ногах: дизайн не может полагаться на то, что сверху или снизу конкретная секция. Редактор CMS меняет порядок.

## Проверка (обязательно, минимум 2 круга)
- Запуск из корня репозитория: `design/tools/run.sh concepts <name>`. Нужен Docker, он есть. Скрипт кладёт в `design/concepts/<name>/shots/`:
  - `first-1440.png`, `first-375.png` (первый экран с анимацией после интро);
  - `page-1440.png`, `page-375.png` (вся страница, reduced motion);
  - `menu-375.png`, `kk-375.png`, `en-375.png`, `n1-375.png`, `n12-375.png`;
  - `n-0-1440.png`, `tone-light-1440.png`, `tone-accent-1440.png`;
  - `scroll-1440.webm`.

  В консоль он пишет ошибки страницы и горизонтальное переполнение — их быть не должно.
- Смотри PNG через Read. Длинные скриншоты сожми или вырежи (`sips -c H W --cropOffset Y X in.png --out out.png`, offset не 0 — используй 1) и разбирай как арт-директор:
  - что видно первым;
  - есть ли один запоминающийся «момент»;
  - где шаблонно, где тесно, где пусто без причины;
  - выдержит ли блок другой текст, язык и число элементов.

  Исправь и сними заново.
- Python и Node на хосте не запускай, только через `design/tools/run.sh` (Docker).
- Git не трогать.
