# Чертёж v2: заметки к прототипу

## Контракт линии

Линия — одна нить через всю страницу. Порядок блоков задаёт редактор CMS, поэтому:

1. **Каждый блок входит в линию в своём верхнем крае и выходит из нижнего в точке поля** `x = --trace-x` (= `0.42 × --pad-l`, у всех секций одинаковый `padding-left`).
2. Внутри блок рисует свой путь, но на краях всегда стоит в поле:
   - hero: линия рождается в точке-начале на горизонте «±0,000» (hero всегда первый);
   - stats: прямая + отвод из поля в размерную линию над главной цифрой;
   - process_steps: закреплённая сцена со своим путём (см. ниже), вход и выход в поле;
   - projects: прямая по полю, мелкие засечки на уровне строк;
   - footer: по полю вниз, затем поворот в штамп листа, конечная марка в штампе.
3. Блок без своего рисунка проводит прямой вертикальный отрезок `(x, 0) → (x, h)`.
4. Цвет — `--trace` тона секции (на accent-тоне графитовый), поэтому стык тонов — просто смена цвета в одной точке.

## Перо и прогресс

Перо стоит на 78% высоты экрана для всех секций. Прогресс секции:

```
p = clamp((scrollY + 0.78·vh − sectionTop) / sectionHeight, 0, 1)
```

Это ровно `useScroll({ target: ref, offset: ['start 78%', 'end 78%'] }).scrollYProgress`. Нижний край секции N и верхний край секции N+1 проходят перо в один и тот же момент, поэтому рисование идёт через стыки без пауз.

## Сцена «Полный цикл» (process_steps)

- Секция-сцена высотой `100svh + N × 65svh` (N — число этапов из данных, 65svh прокрутки на этап, последний держится столько же), внутри `position: sticky; top: 0; height: 100svh` — сцена. `svh`, чтобы на iOS высота не прыгала от адресной строки.
- Состояние задаёт только позиция: `p = (scrollY − sceneTop) / (N × 65svh)`, активный этап `= min(N − 1, floor(p × N))`. Нативная прокрутка, без snap, preventDefault и плавного скролла. После последнего этапа sticky отпускается сам.
- Линия сцены — свой путь в SVG сцены: из поля по пере (до закрепления) → на ось этапов → по узлам непрерывно по p (узел i достигается при p = i/N) → на последнем этапе вниз и обратно в поле → вниз к нижнему краю сцены. На телефоне ось — сама линия в поле, узлы на ней.
- Справа кадр этапа (`MS.plate(step.media)`, кроссфейд + clip). Без фото — один лист чертежа: 12 элементарных слоёв (участок, размеры, план, оси, стены, фасад, панели ×2, каркас, перекрытия, кровля и окна, отметка ±0,000), слой k принадлежит этапу floor(k × N / 12) — при любом N от 1 до 12 у каждого этапа есть слой и нет дублей; слои рисуются по p и остаются.
- Смена этапа: только opacity, transform, clip-path, 400–450 мс, (0.2, 0.7, 0.2, 1).
- Framer: `useScroll({ target: scene, offset: ['start start', 'end end'] })` → p; `useTransform(p, keys, lengths)` → pathLength; активный этап — `useMotionValueEvent(p)`.
- Reduced motion, `?settle=1` и N = 1 — без закрепления: этапы списком, всё раскрыто, линия нарисована.
- Клавиатура: фокус внутри неактивного этапа прокручивает к нему; неактивные панели только прозрачные, не скрыты.
- `?scene=K` — служебный: прокручивает к этапу K (reveals выключены); `?scene=pre` — момент перед закреплением. `_frame.html?w=&h=&q=` — служебная страница для снимка одного экрана в iframe фиксированного размера.

## Перенос на Framer Motion

У каждого пути `pathLength=1`, рисование — `strokeDashoffset = 1 − value`, в Framer это `motion.path` со стилем `pathLength`.

```tsx
const { scrollYProgress } = useScroll({ target: ref, offset: ['start 78%', 'end 78%'] })
// прямой отрезок
const main = scrollYProgress
// путь с поворотами: piecewise-отображение «ключ пера → доля длины» (keysN/lensN из layout())
const main = useTransform(scrollYProgress, keysN, lensN)
// отвод (размерная линия stats)
const branch = useTransform(scrollYProgress, [k0, k1], [0, 1])
<motion.path d={d} style={{ pathLength: main }} />
```

- `keysN`/`lensN` и `k0`/`k1` считаются из геометрии при монтировании и по `ResizeObserver` (в прототипе — `layout()`), а не в кадре.
- Узлы этапов цикла зажигаются через `useMotionValueEvent(main, 'change', …)` по порогам.
- Hero: первые сантиметры линии рисуются на загрузке (`animate` 1.1 с от точки-начала), дальше — по скроллу.
- Шапка: `useMotionValueEvent(scrollY)` по знаку дельты → `y: '-100%'` / `0`.
- Reveals: `whileInView` once; count-up — `animate(0, value)` по визуальной копии числа (финальное число всегда в DOM для скринридеров).

## Производительность

- Один пассивный `scroll` + `requestAnimationFrame`.
- Офсеты и геометрия кэшируются и пересчитываются только по `ResizeObserver` и `resize`; в кадре нет `getBoundingClientRect`.
- Секции, прогресс которых не изменился (далеко выше или ниже экрана, 0 или 1), в кадре не трогаются — пишутся только пути рядом с экраном.
- Анимируются только `stroke-dashoffset`, `transform`, `opacity`, `clip-path`.

## Reduced motion и служебные параметры

- Hero (LCP): h1, подзаголовок и CTA статичны с первого кадра; анимируются только линия, горизонт и рамка кадра. Fallback-шрифт с подогнанными метриками сохраняет число строк h1 (`?fallback=1` — служебная проверка).

- `prefers-reduced-motion`: все пути нарисованы, узлы зажжены, без анимации; меню — только прозрачность.
- `?settle=1` — служебный, для full-page скриншотов: всё сразу в финальном состоянии, как при reduced motion.
- Прогрессивное улучшение: класс `.motion` (скрывающие состояния) ставится из JS вместе с готовым `IntersectionObserver`; без него контент виден сразу.

## Данные

- Пустые поля (год, площадь) на карточках не выводятся; в реестре на десктопе — «—» тоном `--fg-mute`.
- UI-строки, которых нет в общем словаре («Лист», «Условные обозначения», «№»…), лежат в `LOCAL` в `motion.js` — на сайте им место в `frontend/src/i18n`.
