# Lighthouse, этап 5

Lighthouse 13.5.0, mobile (Moto G Power, медленный 4G, симуляция), прод-сборка за Caddy с API и MinIO
на сидах (`design/tools/lighthouse.sh`: свой compose-проект `megasmart-lh`, удаляется после замера).
По 5 прогонов на страницу, в таблице медиана. Отчёты медианных прогонов лежат рядом:
`home-4x.report.html`, `project-4x.report.html`, `*-calibrated.report.json` (их открывает
[Lighthouse Viewer](https://googlechrome.github.io/lighthouse/viewer/)).

## Почему два режима
Замедление CPU по умолчанию (4×) рассчитано на хост с benchmarkIndex около 1500–2000. VM colima
на этой машине (2 ядра, рядом другие стеки) показывает 755–1570, и Lighthouse сам предупреждает в
части прогонов, что устройство медленнее ожидаемого. Поэтому даны оба числа: 4× как есть и 2,6×
(4 × 1150 / 1750), эквивалент штатного замедления для такого хоста. На PageSpeed Insights
ожидается ближе ко второму, но это нужно проверить на реальном домене.

## Что дало результат
1. Ранний старт (`index.html` → `src/api/boot.ts`): запросы settings и страницы и предзагрузка
   картинки первого экрана идут, пока скачивается бандл, а не после него.
2. Framer Motion через `LazyMotion` и компоненты `m`: основной чанк 166,6 → 138,8 КБ gzip, функции
   анимации (28 КБ) догружаются после первого экрана; `CountUp` считает сам на rAF.
3. Блоки ниже первого экрана монтируются по одному в простое браузера, их чанки и чанк анимаций
   грузятся тоже в простое, чтобы не делить сеть с картинкой первого экрана (кроме прогрева по
   наведению на ссылку).
4. Линия меряет секции колбэком ResizeObserver, а не синхронно в layout-эффекте: каждый блок,
   появляясь, больше не заставляет пересчитывать раскладку всей страницы.

## Что не зависит от кода сайта
- **BP 81**: только `is-on-https` (стенд по http).
- **SEO 58**: `is-crawlable` — Caddy ставит `X-Robots-Tag: noindex, nofollow` (прототип скрыт от
  поиска намеренно, переменная `ROBOTS`); `robots-txt` — файла нет, SPA отдаёт вместо него
  `index.html`.
- **LCP > 2,5 с**: на главной и в проекте LCP — первая картинка. Её вес (73 КБ JPEG оригинального
  размера на телефоне) упирается в отсутствие адаптивных вариантов: `buildImageUrl` пока отдаёт
  оригинал, image-proxy запланирован.
