## Роль и цель

Ты senior full-stack инженер и продуктовый дизайнер. Мы делаем корпоративный сайт-лендинг для казахстанского холдинга **MegaSmart** (основатель Сергей Хегай, г. Шымкент).

**Текущий этап — прототип:** красивая, законченная визуально «картинка» на тестовом контенте. При этом архитектура должна быть **production-grade с первого дня**, чтобы на следующем этапе добавить админку (CMS) без переписывания фронта и модели данных.

Главный архитектурный принцип:
- **Ни одного захардкоженного контентного текста или изображения во фронтенде.** Все тексты берутся из БД (PostgreSQL) через API, все изображения лежат в S3-совместимом хранилище (локально MinIO) и отдаются как объекты `Media`.
- Во фронте допустимы только UI-строки интерфейса (кнопки «Подробнее», «Назад», aria-label) — и они тоже в i18n-файлах, а не в JSX.

Целевая аудитория сайта:
1. **Инвесторы и партнёры** — должны увидеть масштаб, историю роста, надёжность и перспективу работы с Сергеем Хегай.
2. **Потенциальные сотрудники / HR** — должны увидеть сильную команду и захотеть работать в холдинге.

## Модель контента (фундамент под CMS) — самое важное

Используй **гибридный подход**: страницы собираются из упорядоченных секций (блоков), а повторяющиеся сущности (проекты, люди, клиенты) — отдельные типизированные коллекции, на которые секции ссылаются.

### Локализация
Сайт на **ru** (основной), **kk** и **en**. Все контентные текстовые поля хранятся как `LocalizedText` — JSONB вида `{"ru": "...", "kk": "...", "en": "..."}`. API принимает `?locale=ru` и отдаёт уже разрешённые строки с fallback на `ru`. Для прототипа заполняем только `ru`, но схема должна поддерживать все три языка.

### Таблицы (минимум)

- **media** — `id (uuid)`, `s3_key`, `bucket`, `mime_type`, `size_bytes`, `width`, `height`, `alt (LocalizedText)`, `blurhash` или `dominant_color`, `created_at`. API отдаёт `url` (публичный или presigned — через абстракцию `StorageService`), `width`, `height`, `alt`, `placeholder`. Ширина/высота обязательны — чтобы не было layout shift.
- **site_settings** (singleton) — название, логотип (media), навигация, контакты, соцсети, футер, SEO по умолчанию.
- **page** — `id`, `slug` (уникальный), `title`, `seo_title`, `seo_description`, `og_image (media)`, `is_published`, `sort_order`.
- **section** — `id`, `page_id`, `type` (enum), `sort_order`, `is_visible`, `anchor` (для якорной навигации), `data (JSONB)`.
  - `data` валидируется Pydantic-схемой **по типу секции** (discriminated union по `type`). Никакого «сырого» JSON без схемы.
- **division** (подразделения холдинга) — `slug`, `name`, `tagline`, `description`, `logo`, `cover`, `stats`, `website_url`, `sort_order`.
- **project** — `slug`, `title`, `division_id`, `status` (`completed` / `in_progress` / `planned`), `location`, `year`, `area_m2`, `short_description`, `body` (rich text/markdown), `cover`, `gallery (many-to-many media с порядком)`, `tags`, `is_featured`, `is_tokenized`.
- **person** (команда) — `full_name`, `position`, `division_id`, `bio`, `photo`, `linkedin_url`, `is_key` (топ-менеджмент), `sort_order`.
- **client** — `name`, `logo`, `industry`, `description`, `testimonial` (опционально), `website_url`, `sort_order`.
- **timeline_event** — `year`, `title`, `description`, `image`, `sort_order`.
- **stat** (цифры) — `value`, `suffix`, `label`, `context` (к какой странице/подразделению относится).
- **vacancy** — заготовка таблицы (`title`, `division_id`, `location`, `employment_type`, `description`, `is_open`) — на прототипе можно 2–3 тестовые.
- **lead** — заявки с форм (`name`, `phone`, `email`, `message`, `type`: investor / partner / candidate / client, `source_page`, `created_at`).

Все таблицы: `created_at`, `updated_at`, у публикуемых — `is_published`. UUID первичные ключи.

### Типы секций (enum `SectionType`) и их Pydantic-схемы
`hero`, `stats`, `about_text`, `timeline`, `divisions_grid`, `projects_showcase`, `project_list`, `capabilities` (иконки + текст), `process_steps` (этапы: земля → проект → стройка → сдача), `production` (производство: мощности, технологии, галерея), `tokenization_explainer`, `team_grid`, `clients_marquee`, `clients_grid`, `testimonials`, `quote` (цитата основателя), `cta`, `contact_form`, `media_gallery`, `video`.

Каждая схема хранит **ссылки** на сущности (например `project_ids`, `person_ids`, `media_id`), а API при отдаче страницы **разворачивает** их в полные объекты, чтобы фронт получал всю страницу одним запросом.

### API (v1)
Публичное, только чтение (+ форма заявки):
- `GET /api/v1/settings?locale=`
- `GET /api/v1/pages/{slug}?locale=` → страница с развёрнутыми секциями
- `GET /api/v1/projects?division=&status=&featured=&locale=`, `GET /api/v1/projects/{slug}`
- `GET /api/v1/people?division=&key=`
- `GET /api/v1/clients`
- `GET /api/v1/vacancies`
- `POST /api/v1/leads` (валидация, rate limit — хотя бы заготовка, honeypot-поле от спама)
- `GET /api/v1/health`

Заготовка под админку (роутеры и структура, без UI):
- `/api/v1/admin/*` — CRUD для всех сущностей, закрыт зависимостью `require_admin` (JWT). На прототипе можно реализовать CRUD для 1–2 сущностей как образец, остальное — TODO, но архитектура (сервисы, репозитории, схемы Create/Update/Read) должна быть одинаковой для всех.
- `POST /api/v1/admin/media/upload-url` — выдача presigned PUT URL в S3 + регистрация записи в `media`. Это ключевой механизм загрузки картинок из будущей админки.

Слои бэкенда: `api/routers` → `services` → `repositories` → `models`. Pydantic-схемы отдельно в `schemas/`. Никакой бизнес-логики в роутерах.

### Сиды
`make seed` должен:
1. Загрузить в MinIO набор плейсхолдер-изображений (положи их в `backend/seed/images/`; бери свободные стоковые фото стройки, архитектуры, производства, офисов — например скачай с Unsplash с указанием источника в `seed/CREDITS.md`, либо генерируй нейтральные градиентные плейсхолдеры, если сеть недоступна).
2. Создать в БД все страницы, секции и сущности с тестовым контентом на русском (см. раздел «Контент» ниже).
3. Быть идемпотентным (повторный запуск не плодит дубли).

## Фронтенд-архитектура

- **Section registry**: объект `sectionRegistry: Record<SectionType, React.FC<Props>>`. Компонент `<PageRenderer slug="..." />` получает страницу из API и рендерит секции по порядку. Добавление нового блока = новая схема на бэке + новый компонент + регистрация. Неизвестный тип — не падать, в dev показывать предупреждение.
- Компонент `<SmartImage media={...} sizes="..." />` — единственный способ вывести картинку: lazy loading, `width/height` из API, placeholder (blurhash/dominant color), `alt` из CMS. Подготовь интерфейс под будущий image-proxy (imgproxy/thumbor) — функция `buildImageUrl(media, {width})`.
- Структура: `src/app` (роутер, провайдеры), `src/pages`, `src/sections`, `src/components/ui` (кнопки, контейнеры, типографика), `src/api` (клиент + сгенерированные типы + query-хуки), `src/i18n`, `src/styles`.
- Состояния загрузки: скелетоны, не спиннеры на весь экран. Ошибки API — аккуратная заглушка.
- Переключатель языка RU / KZ / EN в шапке (локаль в URL: `/ru/...`, `/kk/...`, `/en/...`).
- SEO: title/description/og из API на каждой странице. Отметь в `docs/`, что для продакшена рассмотрим SSR/пререндер (Vite SSR или переезд на Next.js) — но сейчас SPA.

## Дизайн-направление

Референсы по настроению — премиальные корпоративные Wix-шаблоны: «AI-компания (монохромный)» и «Лендинг для запуска (чистый)», плюс контент smartpanels.kz. **Не копируй их вёрстку** — сделай собственный дизайн в этом духе:

- **Настроение**: premium, архитектурный, уверенный. Уровень крупного девелопера/инвестиционного холдинга, а не «сайт мебельного магазина».
- **Палитра**: монохром (почти чёрный `#0E0E0E`, графит, тёплый off-white `#F5F3EF`) + **один акцентный цвет** (например, тёплый бронзовый/медный или насыщенный зелёный — предложи 2 варианта в `docs/design.md` и вынеси в токены, чтобы менять одной переменной). Чередуй тёмные и светлые секции для ритма.
- **Типографика**: крупные заголовки (clamp, до 96–120px на десктопе), контраст размеров. Шрифты обязательно с полной поддержкой **кириллицы и казахских букв** (ә, ғ, қ, ң, ө, ұ, ү, һ, і) — проверь, например Inter / Inter Tight, Onest, Golos Text, Unbounded (для акцентных заголовков). Подключай через self-hosted `@fontsource`, не через Google CDN.
- **Сетка**: 12 колонок, щедрые отступы, асимметричные композиции, крупные фотографии на всю ширину.
- **Анимации**: сдержанные и дорогие — fade/slide-up при появлении, параллакс фото, анимированные счётчики, «прорисовка» линии таймлайна, плавный hover на карточках. Уважай `prefers-reduced-motion`.
- **Мелочи**: кастомный скроллбар не нужен; нужны аккуратные focus-состояния, тонкие разделители, номера секций (01, 02...) как элемент стиля.
- **Адаптив**: mobile-first, проверка на 375 / 768 / 1280 / 1920. Без горизонтального скролла.
- **Доступность**: семантические теги, контраст AA, alt у всех картинок, навигация с клавиатуры.

## Порядок работы

Работай **поэтапно**, после каждого этапа — короткий отчёт и проверки (линтер, типы, тесты), затем коммит с понятным сообщением.

0. **План.** Прочитай задание, задай мне уточняющие вопросы, если что-то критично неясно, покажи план и структуру папок. Создай `CLAUDE.md` с правилами проекта (стек, архитектурные принципы, «никакого захардкоженного контента», команды) и `docs/content-model.md`.
1. **Инфраструктура**: docker-compose (Postgres, MinIO + init), скелет backend и frontend, `.env.example`, Makefile, health-check. Проверка: `make up` поднимает всё.
2. **Backend: модели и миграции** всех сущностей, `StorageService` (S3), Pydantic-схемы секций (discriminated union), репозитории/сервисы.
3. **Backend: публичное API** + разворачивание ссылок в секциях + локализация с fallback + тесты на ключевые эндпоинты.
4. **Сиды**: картинки в MinIO + весь контент. Проверка: `GET /api/v1/pages/home?locale=ru` отдаёт полную страницу.
5. **Frontend: фундамент** — дизайн-токены, типографика, UI-кит (Container, Section, Heading, Button, Tag, SmartImage), шапка, футер, роутинг с локалью, API-клиент и генерация типов, `PageRenderer` + registry.
6. **Frontend: секции и страницы** — по одной странице за раз, начиная с главной. Каждую секцию делай на уровне финального дизайна, не «потом докрасим».
7. **Полировка**: анимации, адаптив на всех брейкпоинтах, скелетоны, 404, SEO-мета, Lighthouse (цель ≥ 90 по Performance/Accessibility/SEO на десктопе).
8. **Заготовка админки**: `require_admin`, JWT, CRUD-образец для `project` и `media` (presigned upload), описание в `docs/admin-roadmap.md`, как дальше строить админку (свой React-интерфейс vs. готовое решение вроде SQLAdmin для старта).

## Правила качества

- TypeScript strict, без `any`. Python — type hints везде, mypy без ошибок.
- Никаких секретов в коде — только `.env`.
- Компоненты небольшие, без копипасты; общие паттерны — в UI-кит.
- Если сомневаешься между «быстро» и «правильно для будущей CMS» — выбирай второе и коротко объясни почему.
- Не придумывай факты о реальных людях и компаниях — только плейсхолдеры с TODO.
- В конце каждого этапа: что сделано, как проверить, что осталось, какие вопросы к бизнесу (для Романа) и к техническому лиду.
