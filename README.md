# MegaSmart

Корпоративный сайт холдинга MegaSmart. Прототип на тестовом контенте: все тексты и картинки лежат в базе и хранилище, фронтенд только рисует то, что отдаёт API. Контент редактируется в админке по адресу `/admin`: страницы и блоки с публикацией и историей версий, медиатека, коллекции, настройки сайта, заявки, пользователи и журнал действий.

## Запуск

Нужен только Docker (Docker Desktop или Colima). Node.js и Python локально не нужны.

```bash
make up        # собрать и запустить контейнеры (создаст .env из .env.example)
make migrate   # создать таблицы
make seed      # загрузить картинки в MinIO и тестовый контент в базу
# первый администратор (пароль спросит):
docker compose -f infra/docker-compose.yml --env-file .env exec backend python -m app.cli create-admin --email you@example.com --name "Имя"
```

Через пару минут:

| Что | Адрес |
|---|---|
| Сайт | http://localhost:5173 |
| Админка (вход под созданным администратором) | http://localhost:5173/admin |
| API и документация | http://localhost:8000/docs |
| MinIO (картинки), логин из `.env` | http://localhost:9001 |

`make seed` наполняет только пустую базу: если контент уже есть, он ничего не меняет, правки редакторов в безопасности. Вернуть стартовый контент в dev — `make seed-force` (перезапишет правки в стартовых записях и удалит добавленные блоки на стартовых страницах).

## Команды

| Команда | Что делает |
|---|---|
| `make up` / `make down` | запустить / остановить |
| `make logs` | логи бэкенда и фронтенда |
| `make migrate` | применить миграции |
| `make seed` | тестовый контент (только в пустую базу) |
| `make seed-force` | перезаписать стартовый контент (только dev) |
| `make lint` | ruff, mypy, eslint, tsc |
| `make fmt` | автоформатирование |
| `make test` | тесты бэкенда (pytest) и фронтенда (vitest) |
| `make e2e` | сквозные тесты админки и сайта (Playwright) в отдельной копии стека со своей базой; вашу базу не трогает |
| `make gen-types` | обновить TypeScript-типы из OpenAPI бэкенда |
| `make reset` | удалить все данные (база и картинки) |

## Как устроено

- **Страница = список секций в базе.** Каждая секция имеет тип (`hero`, `stats`, `timeline`…) и данные, которые проверяет Pydantic-схема. Правки делаются через админское API и попадают на сайт после публикации страницы: сайт показывает опубликованную версию, а не черновик.
- **Секции ссылаются на сущности** (проекты, люди, клиенты) по id. API разворачивает ссылки, и фронтенд получает всю страницу одним запросом.
- **Языки:** ru, kk, en. Тексты хранятся как `{"ru": "...", "kk": "...", "en": "..."}`. Если перевода нет, показывается русский.
- **Картинки** лежат в S3 (локально MinIO) и выводятся только через компонент `SmartImage`.
