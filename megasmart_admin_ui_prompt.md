## Задача

Бэкенд CMS готов: админское API `/api/v1/admin/*` (90 операций), публикация с черновиками и версиями, медиатека в S3, журнал действий. Документация — `docs/admin-api.md`, `docs/content-model.md`, `docs/architecture.md`. Прочитай их первыми.

Нужно сделать **интерфейс админки**: удобный, аккуратный, адаптивный, на русском языке. Через него редактор без знания кода меняет всё на сайте: тексты на трёх языках, картинки, блоки страниц и их порядок, проекты, людей, клиентов, меню, контакты, разбирает заявки и публикует изменения.

Главный принцип: **админка не знает про конкретный контент.** Формы блоков строятся из `GET /admin/section-types` (JSON Schema с подсказками `x-widget`, `x-ref`, `x-options`, `x-enum-labels`), списки вариантов — из `GET /admin/meta`. Новый тип блока на бэкенде должен появиться в админке без правки её кода. Если для формы не хватает подсказки, её добавляют на бэкенде, а не зашивают во фронт.

Если ещё не исправлено: в OpenAPI повторяются `operationId` (`get_page` и `get_settings` в публичном и админском API, `list_items`/`create_item`/`get_item`/`update_item`/`delete_item`/`reorder_items` по 7 раз). ## Где живёт админка — решить на этапе 0

Важное ограничение: админка, API и сайт открываются с **одного домена** (refresh-cookie `SameSite=Strict`, путь `/api/v1/admin/auth`), см. `docs/architecture.md`, раздел «Деплой».

Варианты:
1. **Маршрут `/admin` внутри `frontend/`, загружаемый отдельным чанком (`React.lazy`).** Без новой инфраструктуры, один контейнер и один билд. Общие API-клиент, типы и компоненты блоков для предпросмотра. Код админки не должен попадать в бандл сайта — проверить размер бандла до и после.
2. **Отдельное приложение `admin/` в монорепозитории.** Полная изоляция зависимостей, но нужны новый сервис в docker-compose, правки Dockerfile.prod и Caddyfile.

Мой предпочтительный вариант — первый. Оцени и дай рекомендацию.

## Дизайн

- **Отдельный от сайта стиль:** спокойный, рабочий, светлый по умолчанию, плюс тёмная тема. Акцентный цвет можно взять из токенов сайта. Плотность информации выше, чем на сайте; анимации минимальные.
- **Адаптивность обязательна:**
  - десктоп (≥1280): боковое меню, таблицы, редактор блоков с панелью предпросмотра рядом;
  - планшет (768–1279): боковое меню сворачивается в иконки, предпросмотр — по кнопке;
  - телефон (375–767): нижняя навигация или меню-шторка, таблицы превращаются в карточки, формы в одну колонку, все действия достижимы пальцем (цели нажатия ≥ 44px). На телефоне должны быть удобны как минимум заявки, правка текстов и публикация.
- **Доступность:** работа с клавиатуры, видимый фокус, подписи у полей, контраст AA, `prefers-reduced-motion`.
- **Состояния:** скелетоны при загрузке, понятные пустые состояния («Проектов пока нет — добавьте первый»), подтверждение опасных действий, уведомления об успехе и ошибках.

## Сквозная механика

### Вход и сессия
- Страница входа, выход, смена своего пароля.
- Access-токен хранится в памяти, не в `localStorage`. При загрузке страницы сессия восстанавливается через `POST /admin/auth/refresh` (cookie).
- **Обновление токена — в одном месте:** один общий запрос на все параллельные вызовы, плюс координация между вкладками (`navigator.locks` или `BroadcastChannel`). Иначе две вкладки отзовут сессию друг у друга — см. `docs/admin-api.md`.
- На 401 — одна попытка обновить токен и повторить запрос, иначе переход на вход с возвратом на текущую страницу.
- Меню и действия зависят от роли: `editor` не видит пользователей, журнал и настройки сайта.

### Ошибки и конфликты
- Единый разбор формата `{error: {code, message, details}}`.
- 422: ошибки привязываются к полям формы по `loc` (включая вложенные пути вроде `data.steps.0.title.ru`) и подсвечиваются; если поле не найдено, ошибка показывается над формой.
- 409 `VERSION_CONFLICT`: диалог «Запись изменили, пока вы её редактировали» с выбором «Загрузить свежую версию» или «Остаться и скопировать свои правки». Молча затирать нельзя.
- 409 `IN_USE`: список мест, где используется объект, со ссылками на них.
- **Несохранённые изменения:** предупреждение при уходе со страницы и закрытии вкладки; сохранение по Cmd/Ctrl+S.

### Многоязычные поля
- Поле `LocalizedText` — вкладки RU / KZ / EN рядом с полем (или один переключатель языка на всю форму, предложи вариант).
- Видно, какие языки заполнены. Пустой KZ/EN помечен «будет показан русский текст».
- Обязательный русский текст подсвечивается, если пуст.

## Конструктор форм по схеме (ядро админки)

Компонент `SchemaForm`, который по JSON Schema из `section-types` строит форму, а результат отдаёт в формате хранимых данных блока.

| Подсказка в схеме | Виджет |
|---|---|
| `x-widget: localized-text` / `localized-textarea` | многоязычное поле, одна строка / многострочное |
| `x-widget: markdown` | редактор Markdown с предпросмотром (тем же компонентом `Markdown`, что на сайте) |
| `x-ref: {kind: media}` | выбор файла из медиатеки (с загрузкой нового прямо из окна), превью; `many: true` — упорядоченный список с перетаскиванием |
| `x-ref: {kind: project / person / client / ...}` | выбор сущности через `GET /admin/lookup` с поиском и карточками; `many: true` — упорядоченный список |
| `x-widget: select` + `x-options` | выпадающий список из `meta` (наборы цифр, направления) |
| `x-enum-labels` | выпадающий список или переключатель с русскими подписями |
| `x-widget: icon` | сетка иконок сайта с поиском |
| `x-widget: link` | выбор цели ссылки: страница, проект, якорь, внешний адрес |
| `x-widget: color` | палитра + ввод hex |
| `type: array` объектов | список карточек: добавить, удалить, свернуть, перетащить |
| вложенный объект | группа полей |
| `boolean`, `number`, `string` | переключатель, число, поле ввода; ограничения (`minLength`, `pattern`, `maximum`) проверяются на клиенте |
| неизвестный виджет | поле JSON с проверкой и предупреждением для разработчика в консоли |

Подписи полей и подсказки берутся из `title` и `description` схемы. `SchemaForm` покрывается unit-тестами на каждый виджет и на привязку ошибок 422.

Тот же `SchemaForm` используется для коллекций и настроек, если для них есть схемы. Где схемы бэкенда не хватает подсказок, предложи их добавить на бэкенде (добавочно), а не писать формы руками.

## Разделы

### 1. Главная (дашборд)
- Новые заявки (число и последние 5).
- Страницы с неопубликованными изменениями.
- Последние действия из журнала (для `admin`).
- Быстрые действия: «Новый проект», «Загрузить файлы», «Заявки».

### 2. Страницы
- **Список:** название, адрес, статус («На сайте», «Есть неопубликованные изменения», «Снята», «Не публиковалась»), дата публикации, перетаскивание порядка.
- **Редактор страницы:**
  - верх: название, статус, кнопки «Предпросмотр», «Опубликовать» (с комментарием), меню «Сбросить черновик», «Снять с сайта», «История версий»;
  - вкладка «Блоки»: список блоков с типом, превью заголовка, перетаскиванием, скрытием, копированием, удалением; «Добавить блок» — окно выбора типа из `section-types` (название, описание), вставка в выбранное место;
  - правка блока — `SchemaForm` в боковой панели или на отдельном экране (на телефоне);
  - вкладка «Настройки и SEO»: адрес, многоязычные название, SEO-заголовок и описание, картинка для соцсетей;
  - на десктопе — панель предпросмотра (iframe маршрута предпросмотра сайта), обновляется после сохранения.
- **Публикация:**
  - кнопка неактивна, если изменений нет и страница на сайте;
  - отправляется `draft_hash`, полученный при загрузке страницы;
  - 422 при публикации — список проблем с переходом к нужному блоку и полю;
  - `DRAFT_CHANGED` — «Страницу изменили, обновите и проверьте».
- **История версий:** список с номером, автором, датой, комментарием, отметкой текущей; просмотр снимка; «Восстановить» и «Восстановить и опубликовать».

### 3. Предпросмотр на сайте
- В публичной части сайта маршрут `/:locale/preview/:slug?token=…`: та же страница через `PageRenderer`, но данные из `GET /api/v1/preview/pages/{slug}`. Плашка «Предпросмотр — это не опубликованная версия», `noindex`.
- Это единственная разрешённая правка публичной части; бандл сайта не должен заметно вырасти.

### 4. Медиатека
- Сетка с превью и список; фильтры по типу и папке, поиск, теги.
- **Загрузка:** перетаскивание нескольких файлов, прогресс по каждому, три шага (`upload-url` → PUT в S3 → `complete`), показ предупреждений (например, о вырезанных частях SVG или размерах видео), понятные ошибки типа и размера.
- **Карточка файла:** превью, размеры, вес, подпись (alt) на трёх языках, папка, теги, «Где используется», удаление (с показом мест при 409).
- Тот же компонент в режиме выбора — окно для `x-ref: media`.

### 5. Коллекции
Направления, проекты, сотрудники, клиенты, история, цифры, вакансии.
- Общий шаблон: таблица (карточки на телефоне), поиск, фильтры, сортировка, перетаскивание порядка, переключатель «На сайте».
- Форма создания и правки; у проекта — галерея с перетаскиванием.
- Удаление с показом мест при 409.
- Конфигурация отличий коллекций (колонки, фильтры) — в одном объявлении на коллекцию, без копирования страниц.

### 6. Настройки сайта (только admin)
Название, логотип, меню (добавить, удалить, перетащить, цель пункта), контакты, соцсети, подвал, SEO по умолчанию. Сохранение целиком с версией.

### 7. Заявки
Таблица (карточки на телефоне) с фильтрами по теме, статусу и периоду, поиск, смена статуса в один клик, заметка менеджера, выгрузка CSV по текущим фильтрам, счётчик новых в меню.

### 8. Пользователи (только admin)
Список, создание, роль, отключение и включение, сброс пароля. Защита от самоблокировки показывается понятным текстом.

### 9. Журнал действий (только admin)
Список с фильтрами по пользователю, сущности и периоду; раскрытие записи с разницей «было → стало» по полям.
